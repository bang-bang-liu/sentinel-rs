# 源码发布与数据边界

此仓库只包含应用源码、依赖锁文件、合成测试、部署模板和脱敏文档。账号数据由部署方保管。

## 发布清理

已移除或泛化开发机路径、服务器别名和身份、真实部署版本、账号数量、账号 ID、任务 ID、账号库指纹及私有验证记录。测试邮箱统一使用保留域 `example.invalid`，测试凭据为明确的合成字符串。

发布路径中保留的 `127.0.0.1` 是程序回环监听地址，`chatgpt.com` 是目标服务域名；部署脚本中的 `/opt/sentinel-offers` 和 `/var/lib/sentinel-rs` 等是默认目录模板。它们不包含服务器 IP、用户名或密钥。

`offers-host` 是 SSH 配置别名示例，需要自行配置，不能直接指向任何真实服务器。

## 不提交的材料

`.gitignore` 排除运行配置、管理口令、账号及结果数据库、SQLite 辅助文件、查询导出、日志、截图、QA 目录、归档、密钥和原始验证 JSON。示例配置 `deploy/offers.env.example` 只含空代理与非秘密默认值。

已有真实 `offers.db`、账号库和管理口令不通过修改内容来制作示例。原始联机验证材料保留在源码目录外、仅部署方可读的目录中；源码发布不会改写运行中的账号数据。

发布前执行 `python deploy/audit_publication.py --git-staged` 扫描暂存区。该检查拒绝数据库、真实邮箱、非示例地址、常见密钥格式、生产目录验证快照及凭据赋值，并只报告文件、行号和问题类型，不输出命中的值。它不能代替人工审阅提交文件列表。

也可使用 `python deploy/audit_publication.py --root PATH` 扫描不含 .git/target/私有材料的工作目录。发布方仍应核对 Git 历史，避免先提交秘密再从当前版本删除。
